Tabla de rastro: apoyo_cargue_asignaciones

Auditoría de qué personas fueron agregadas (aparte de Picking/Packing) a una orden de Cargue/Descargue. Es también la llave que usa el fix de pagonomina (paso 3) para permitirle el bono de toneladas a alguien de especialidad=true solo el día en que tiene una fila aquí.

Troubleshooting — "no veo el módulo nuevo en el menú"

Pasa después de correr el script 2 (o cualquier permiso nuevo) y dar el toggle en Gestión de Usuarios, si la pestaña de LIPgo ya estaba abierta desde antes del despliegue.

✓ Verificado — no es la base de datos

La columna apoyo_cargue y la tabla apoyo_cargue_asignaciones existen; el toggle en Gestión de Usuarios sí guarda el permiso en permisos_usuarios correctamente (confirmado con datos reales).

✓ Verificado — no es el código

El sidebar (components/sidebar.tsx) resuelve visibilidad SIEMPRE contra MODULE_PERMISSION_MAP — mismo origen que usa Gestión de Usuarios para construir el árbol de permisos. Sin listas paralelas, sin nombres desalineados.

⚠ Causa real

El sidebar sí trae los permisos frescos en cada carga (cache: "no-store"), pero el listado de módulos posibles (incluido el nuevo) vive en el JavaScript ya cargado en la pestaña del navegador. Si la pestaña de LIPgo llevaba abierta desde antes del git push, sigue corriendo el bundle viejo — que ni siquiera sabe que el módulo nuevo existe.

Solución
  1. Cerrar por completo la pestaña/ventana de LIPgo (no solo navegar dentro de la app).
  2. Abrirla de nuevo, o hacer un refresco duro (Ctrl+Shift+R).
  3. Confirmar con qué correo quedó iniciada la sesión — el permiso debe estar en true para ese usuario específico, no otro.
Todos verificados contra tsc --noEmit y datos reales antes de pushear a main.
